# Editor — project-specific agent guidance

**Canonical owner:** Project/content authoring tools, document lifecycle, config inspection, references, validation, visual/Rule preview and data export.

Read root agent guidance first.

- [v0.5.10 DC16](../harness/checkpoints/document-v0.5.10.md) adds explicit compatibility inspection and one-step migration (133 root symbols). Only envelope schema 1 is interpretable; target owner/kind/content version are caller-bound. Current strict-valid content is writable-compatible, never a write permit. Older data is read-only; only an exact named forward step can run. Trusted synchronous pure owner callback produces a candidate through bounded codec capture, conservative additive preservation and canonical post-validation. Every old key/value and array position must survive or the step blocks, including unknown fields and identities. Future schema is rejected; no downgrade, chaining, registry, auto-open migration, IO or session/baseline mutation. Callback semantics remain owner responsibility. The historical Asset demo uses explicit document-content profiles 1 -> 2; published Asset schema and envelope stay 1. Save remains a separate existing operation; no v0.5.11 implementation.

- [v0.5.9 DC15](../harness/checkpoints/document-v0.5.9.md) adds safe persistence diagnostics, optional failed-write reasons and an optional once-per-request host cleanup hook (128 root symbols). Keep primary commit result separate from cleanup result; thrown/malformed commit receipts remain uncertain and quarantined even if cleanup succeeds. Hosts release handles before settling commit, retain potential sole valid payloads and never republish/delete destination during cleanup. No configured recovery/reconciliation/unlock, retry or filesystem adapter is supplied by the portable Editor API. Read/pre-dispatch unexpected errors still propagate.

- [v0.5.8 DC14](../harness/checkpoints/document-v0.5.8.md) adds saveDocument plus five write-precondition/request/receipt/port/result types (125 root symbols). Open session -> exact ticket -> canonical serialize/strict diagnostics -> conditional host commit -> exact-ticket acknowledgement. A later edit stays dirty after an older commit. Host must promise atomic full-payload publication AND atomic precondition enforcement; unknown tokens or unsupported guarantees block without IO. create-only permits absent targets only; existing-file revision writes require actual compare-and-swap. Never implement read/hash then unconditional rename as CAS. Same-session concurrent calls return busy; uncertain/thrown/malformed commit receipts keep baseline unchanged and block subsequent coordinator writes on that session. No recovery API/retry yet. Closed-while-pending may commit storage but returns session-closed acknowledgement without reopening/clearing state. Actual IO remains host-owned and portable root has no platform imports. Local manual host demonstrates staged hardlink create-only, not replacement CAS or crash durability. No v0.5.9.
