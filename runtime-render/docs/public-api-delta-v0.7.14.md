## Semantic compatibility and within-phase extensions

Legacy signature identity is compile evidence only. `prepareVisualResource` source is
byte-for-byte unchanged from Phase 6: synchronous detached metadata, NOT_PERFORMED.
`createRenderFrameSession` still delegates to the canonical lazy acquisition; plain
`renderFrame()` keeps clear-only submission, target guards, suspension/invalidation
and terminal loss policy. New texture/session cleanup hooks run only for owned new
resources; the new demo takes an explicit live texture, never attaches a Scene.

v0.7.10 adds optional maxRevisionEntries/revisionEntries and a fourth optional parser
limits argument to the v0.7.9/v0.7.5 APIs. Existing call shapes remain accepted; guards
are opt-in via invalidation. v0.7.8 broadens PNG handle ownership documentation to
include scoped aliases. v0.7.13 registers private backing identity/canonical geometry
for drawing; no native handle, private API or new legacy failure-union member escapes.

The inherited Phase 6 diagnostic expansion/migration decision is already recorded in
[its closure](../../harness/checkpoints/render-viewport-v0.6.14.md); this phase does not
reopen it or claim its pending browser evidence. Unexpected provider/native exceptions
remain original on lifecycle APIs; the older one-shot acquireVisualSource deliberately
classifies provider rejections as PROVIDER_FAILED. These are separate documented APIs.
